# Design-language provenance — non-normative research reference

This document preserves historical visual research in its original language. It is non-normative unless a rule is explicitly promoted into [SKILL.md](../SKILL.md), which takes precedence. Historical headings such as “Hard Lock” and “可执行规则” do not make these passages current requirements: fixed composition skeletons, node counts, subject ratios, quiet-area percentages, depth counts, and specific motifs must not silently become templates.

下面这套规范是从你提供的 9 张参考图中抽取共同结构后重新组织出来的。它保留的是视觉系统的生成逻辑，而不是某张图的表面元素。

# 设计语言名称

**观测图谱式视觉系统**

英文工作名可用：**Observed Atlas System / OAS**

这个名称只是为了方便后续讨论，不对应任何参考作品名称。

# 核心定义

### 观察到的事实

参考图反复出现几类稳定特征：

* 主体通常不是单独展示，而是被坐标、圆弧、测量线、编号、框线、节点等“分析系统”包围。
* 画面经常存在一条极强的主轴：垂直轴、水平轴、圆心轴或中心交叉轴。
* 视觉重心高度集中，但信息密度并不均匀，主体附近极密，外围明显变稀。
* 图像同时混合摄影、剪影、线稿、建筑、人物、动物、机械结构等不同媒介。
* 蓝色承担非常明确的强调作用，而不是平均铺满画面。
* 灰白、黑色构成主体信息场，蓝色负责激活节点和建立路径。
* 文字经常侵入图像，而不是与图像分别占据整齐独立的版块。
* 几何结构大量存在，但许多几何形态具有“测量、定位、追踪、切片、编号”的语义。
* 画面普遍存在颗粒、网点、扫描、复印、抖动、半透明、阈值化等材质层。

### 设计推断

这套设计语言的真正核心不是“蓝白科技感”。

它更接近：

**把一个普通主题重新包装成“正在被记录、分析、定位和解释的对象”。**

因此视觉关系应当是：

**主题实体 + 观察系统 + 信息痕迹**

而不是：

**主题实体 + 随机科技装饰。**

它同时存在两套语言：

一套负责“叙事”——人物、动物、建筑、产品、物体。

另一套负责“解释”——编号、坐标、几何、轨迹、框选、参数。

两套语言必须相互穿插。

### 可执行规则

任何新主题都先转化成三层：

**对象层**：我要展示什么？

**结构层**：它如何被定位、连接、测量？

**注释层**：用户应该从哪里开始看，并沿什么路径阅读？

如果作品缺少其中一层，就不属于完整的这套系统。

# Hard Lock：必须保留的结构规律

### 观察到的事实

最稳定的不是具体的手、鸟、柱子或角色，而是以下结构：

1. 至少存在一个非常明确的视觉锚点。
2. 有贯穿画面的隐形或显形轴线。
3. 画面不是均匀填充，而是“密集核心 + 稀疏外围”。
4. 主体与辅助图形发生穿插和遮挡。
5. 至少存在一套用于连接不同元素的视觉语法。
6. 强调色只占据有限区域。
7. 大量细节的尺寸远小于主体。
8. 信息存在明显的主次层级。

### 设计推断

这些因素共同制造了“复杂但不是杂乱”的感觉。

真正保持一致性的东西是**信息组织方法**，而不是某个纹理或者颜色。

### 可执行规则

以下规律定义为 Hard Lock：

* 一个画面只能有 **1 个一级视觉中心**。
* 最多允许 **2–4 个二级视觉节点**。
* 必须存在至少一条主组织轴。
* 一级主体尺度明显高于所有注释元素。
* 大量小元素必须依附于一个共同坐标系统，而不能各自漂浮。
* 主体必须至少被一种几何系统“解释”：框选、圆心、坐标、轨迹、切片、连线任选其一。
* 强调色不得平均分布。
* 高密度区域不得覆盖整个画面。
* 前景、中层、背景至少形成三个视觉深度。
* 辅助信息可以复杂，但一级内容必须能在约 1 秒内被识别。

# Soft Lock：可以变化的视觉参数

### 观察到的事实

参考图虽然共有结构，但横版、竖版、UI 页面、封面以及实验海报之间差异很大。

### 设计推断

因此表现手段本身并不是必须固定的。

真正应该固定的是关系，不是形式。

### 可执行规则

以下内容允许自由变化：

* 横版、竖版、方形。
* 摄影、3D、插画、线稿、剪影。
* 中轴构图或偏心构图。
* 主色从蓝色切换到其他高纯度冷色或主题色。
* 无衬线、衬线、等宽字体的具体组合。
* 圆、矩形、三角形的比例。
* 颗粒强度。
* 背景明暗。
* 写实程度。
* 辅助文本多少。
* 几何结构的复杂程度。
* 动态轨迹是曲线还是折线。
* 对称性强弱。

但变化之后仍然必须满足 Hard Lock。

# Must Replace：每次创作必须替换的内容

这是原创化最重要的一部分。

### 观察到的事实

参考图中最容易被表面模仿的是：

手、鸟、圆环、枪械、柱式建筑、人物剪影、蓝色矩形、数学公式、字母坐标和编号。

### 设计推断

这些不是设计语言本身，而是设计语言承载的“词汇”。

只换标题而保留这些词汇，会非常接近临摹。

### 可执行规则

每次更换主题时必须重新生成：

* 一级主体。
* 二级图像素材。
* 图像姿态。
* 象征物。
* 编号体系。
* 坐标含义。
* 标签文字。
* 参数内容。
* 数据形态。
* 图标。
* 辅助符号。
* 图像裁切方式。
* 节点位置。
* 主视觉几何结构。
* 内容之间的连接逻辑。

比如新主题是音乐，就不要机械复制鸟、手、公式。

应该生成属于音乐的结构语言：

波形、频率、节拍、音轨、时间码、声场方向、采样窗口等。

如果主题是植物，则可以转换成：

生长节点、枝干路径、叶片编号、时间轴、样本框、分类索引。

**语法保留，词汇重写。**

# 构图规则

## 观察到的事实

参考图主要出现三种构图骨架。

第一种是**中心轴型**。

一个人物、建筑、装置或物体处于中央，圆、射线和其他结构围绕中心展开。

第二种是**横向轨迹型**。

多个对象沿一条隐形曲线、基线或者时间轴移动。

第三种是**分层档案型**。

画面被分成若干横向区域，每一区域内部发生独立拼贴，同时又通过颜色或者曲线连接起来。

## 设计推断

三种结构实际上对应三种叙事方式：

中心轴型 = “研究这个对象”。

横向轨迹型 = “观察一个过程”。

分层档案型 = “浏览多个片段”。

## 可执行规则

开始设计前必须先选择其中一个骨架，不允许先堆素材再寻找构图。

推荐比例：

一级视觉主体约覆盖画面的 **20%–45%**。

二级信息密集带控制在约 **25%–45%**。

其余区域承担呼吸和延伸。

这些比例是根据参考图总结出的设计建议，并非对原图的精确测量值。

主体可以突破中心，但主重心不能模糊。

# 字体规则

## 观察到的事实

文字大体分成两种角色：

一类承担标题和文化气质。

另一类承担系统信息和标注。

二者字号差异明显。

小字有时非常小，类似技术文档、坐标、档案编号。

## 设计推断

字体实际上在模拟两套声音：

**叙事声音**与**系统声音**。

标题告诉用户“这是什么”。

小字告诉用户“这个东西正在被研究”。

## 可执行规则

建议建立四级文字：

**T1 主标题**

最大的语言单位。

允许与主体发生遮挡、穿插。

**T2 副标题**

说明项目、主题或章节。

不应与 T1 争夺视觉中心。

**T3 系统标签**

如：

A03、NODE 7、SECTION B、INDEX 04。

尺寸明显更小。

**T4 微注释**

用于参数、时间、坐标、编号、描述。

整体形成文字纹理。

字体组合建议：

标题可以使用有明显个性的衬线体或具有结构感的中文字体。

功能信息使用中性无衬线字体。

数据、坐标、编号可使用等宽字体。

最多保持 **2–3 个字体家族**。

重点不是“字体多”，而是“字号跨度大”。

# 几何规则

这是整套语言里最关键的一项。

## 观察到的事实

参考图反复出现：

* 圆。
* 同心圆。
* 半圆。
* 圆弧。
* 十字准星。
* 水平线。
* 垂直线。
* 辐射线。
* 网格。
* 矩形框。
* 虚线。
* 曲线轨迹。
* 节点。
* 刻度。
* 坐标。
* 几何切片。

## 设计推断

它们并非具有同样职责。

不同几何元素实际承担不同的信息功能。

## 可执行规则

必须明确其职责。

**圆 / 圆环**

用于：

定位、中心、作用范围、影响范围。

不要纯粹因为“好看”放圆。

**十字 / 准星**

用于：

精确目标、关键节点、选中状态。

**长直线**

用于：

建立轴线、测量、跨区连接。

**曲线**

用于：

运动、时间、传播、关系。

**矩形框**

用于：

截取样本、局部观察、界面模块。

**网格**

用于：

建立统一坐标空间。

它应该位于低层，而不是抢视觉。

**数字**

用于：

索引。

数字必须能够形成某种潜在规则，即便用户并不知道完整数据。

**小圆点**

用于：

建立节奏、采样点、节点。

不要把它们当随机星星撒满画面。

# 色彩规则

## 观察到的事实

参考图中色彩具有非常明显的层级：

大面积为：

白、灰、黑、低饱和颜色。

高纯度蓝色只出现在局部。

部分作品加入少量红、橙、青、洋红作为局部异常信号。

## 设计推断

颜色承担的不是情绪渲染，而是**信息状态区分**。

因此蓝色效果强，是因为它与大面积中性色形成极高的信息差。

## 可执行规则

建立三类颜色：

**Base / 基础色**

约占 70%–90%。

灰白、冷灰、黑、低饱和主题图像。

**Signal / 信号色**

约占 5%–20%。

用于：

节点、路径、标题局部、选择状态。

**Exception / 异常色**

约占 0%–5%。

红、橙、紫等。

只用于异常、警告、特殊对象。

不要把 Signal 色变成背景主色，否则它失去“信号”作用。

如果主题需要换色，可以：

蓝 → 荧光绿
蓝 → 紫
蓝 → 朱红
蓝 → 青

但是必须继续保持：

**中性色信息场 + 单一主信号色。**

# 密度与留白规则

## 观察到的事实

很多画面第一眼看起来复杂，但实际上并不是全画面复杂。

通常存在：

高密度核心。

中密度连接区域。

低密度背景。

## 设计推断

这就是这些画面没有完全崩成“视觉噪音”的原因。

复杂设计必须依赖空白才能显得复杂。

如果所有位置都复杂，则不存在复杂与简单的对比。

## 可执行规则

把画面划成三类区域：

**D3 高密度区**

主体 + 标题 + 核心几何。

只能有少数几个。

**D2 中密度区**

连接线、数据、标签。

承担过渡。

**D1 低密度区**

只保留非常淡的纹理、网格或轮廓。

建议：

至少保留约 **25%–40% 的视觉低密度区域**。

这不是要求纯白。

这里的“留白”是**信息留白**。

即便存在微弱颗粒，也可以属于留白。

# 材质与叠层

## 观察到的事实

参考图大量使用不同视觉媒介同时存在：

摄影。

阈值图。

线稿。

描边。

剪影。

颗粒。

扫描纹理。

半透明图层。

失真。

网点。

模糊。

硬边矩形。

## 设计推断

这些材质实际上在区分不同“信息来源”。

例如：

摄影像现实数据。

线稿像分析结果。

几何像系统标记。

颗粒像存档介质。

因此材质差异可以形成信息层级。

## 可执行规则

推荐固定五层：

**L0 环境层**

纯色、颗粒、模糊背景。

**L1 语境层**

建筑、空间、风景、弱化照片。

**L2 主体层**

人物、产品、物体。

对比度最高。

**L3 分析层**

圆、坐标、线、网格。

**L4 信息层**

文字、编号、UI 标签。

必要时增加：

**L5 异常层**

颜色偏移、扫描条、像素、色散。

不要让所有图层使用同一种滤镜。

# 禁止事项

## 观察到的失败风险

这种视觉非常容易被简化成几个符号：

“蓝色 + 手 + 圆 + 英文 + 公式”。

这种处理只能复现表象。

## 可执行规则

禁止：

* 从参考图照搬手势。
* 照搬鸟群。
* 照搬建筑轮廓。
* 照搬人物姿态。
* 照搬圆环位置。
* 照搬编号。
* 照搬数学公式。
* 为了“高级感”加入无意义英文。
* 为了“科技感”加入无意义坐标。
* 每一个空隙都塞满元素。
* 每个元素都使用高对比度。
* 大面积使用同一种蓝色。
* 所有文字都变成极小字号。
* 几何图形完全没有对应对象。
* 加一层噪点滤镜就称为完成。
* 只把原来的主体换掉，其余版式原封不动。

尤其禁止一种常见做法：

**先做好普通海报，最后随手叠几个圆、坐标、网格。**

这些图形必须参与构图，而不是作为最后添加的 decoration。

# 生成流程

### 1. 定义主题对象

先用一句话定义：

“这张图究竟在观察什么？”

例如：

“一个城市夜间交通系统。”

而不是：

“做一张科技风海报。”

### 2. 建立主题词汇表

列出 10–20 个属于这个主题的元素。

例如交通主题：

道路、车辆、信号灯、轨迹、站点、时刻、速度、路口。

禁止先使用参考图里的视觉词汇。

### 3. 选择构图骨架

三选一：

中心研究型。

横向过程型。

分层档案型。

### 4. 建立主轴

确定：

X 轴、Y 轴、中心点或者运动路径。

后续所有元素尽可能与它发生关系。

### 5. 放一级主体

此时画面只能有：

背景 + 主体。

先保证不依靠装饰也成立。

### 6. 添加二级对象

通常 2–4 个。

用尺寸、透明度或裁剪降低等级。

### 7. 建立分析系统

此时才开始加入：

圆、框、刻度、轨迹、节点。

每加入一个元素，都必须回答：

**它正在解释什么？**

回答不出来就删除。

### 8. 建立信息系统

加入：

标题。

编号。

数据。

标注。

不要全部使用正文语句。

信息形式需要产生尺寸差异。

### 9. 添加材质

最后才加入：

颗粒。

阈值。

网点。

扫描。

透明层。

### 10. 色彩编码

先完成灰阶版本。

灰阶层级成立以后，再加入 Signal 色。

这是避免“靠蓝色救画面”的重要方法。

### 11. 删除 20%

最后主动删除一批：

线。

数字。

圆。

纹理。

装饰。

如果删除之后反而更清晰，说明它原本就没有职责。

# 海报中的应用

海报应当强化“单帧信息爆发”。

一级标题允许与主体大面积交叠。

可以使用：

中心主体 + 放射系统。

或者：

横向轨迹 + 连续对象。

重点是：

**远看先读主体，近看才发现大量信息。**

不要远看就成为一堆碎片。

---

# 前端页面中的应用

前端不能完全照搬海报逻辑。

### 设计推断

静态海报允许部分信息只是氛围信息。

UI 中的几何和标签会被用户默认理解成“可交互”。

因此需要更严格的功能映射。

### 可执行规则

网页可以这样转换：

主轴 → 页面滚动路线。

节点 → Section Anchor。

圆环 → 当前选中状态。

编号 → 页面章节。

轨迹 → Scroll Progress。

矩形框 → Card / Viewport。

技术注释 → Metadata。

高亮色 → Active / Hover / Selected。

在前端尤其要遵守：

**功能元素的视觉权重 > 装饰元素。**

装饰不得看起来像按钮。

微型文字不得承担关键交互信息。

---

# 宣传图中的应用

宣传图一般比完整海报信息更少。

推荐保留：

主体。

一个主几何结构。

标题。

1–3 个标签。

一个信号色。

大量留白。

也就是说：

**不要为了保持这种视觉语言，把完整系统全部压进一张社交媒体宣传图。**

可以只使用整个系统的一个“切片”。

### 结构

* 能否在 1 秒内找到一级主体？
* 一级主体是否只有一个？
* 是否存在明确主轴？
* 辅助元素是否围绕主轴组织？
* 是否存在 D1 / D2 / D3 密度区别？

### 信息

* 标题是否比技术标注明显？
* 小字是否确实属于辅助信息？
* 每个编号是否具有索引意义？
* 是否存在无意义英文或伪数据？

### 几何

* 每个主要圆、线、框能否解释其职责？
* 删除某个几何图形以后是否毫无影响？
* 如果是，则考虑删除。

### 色彩

* 强调色是否只用于关键信息？
* 是否出现太多高饱和颜色？
* 灰阶模式下构图是否依然成立？

### 材质

* 图层之间是否存在材质差异？
* 是否所有元素都被同一层噪点覆盖？
* 颗粒是否影响正文可读性？

### 原创性

* 是否直接复制了参考图的具体物件？
* 是否复制了具体姿态？
* 是否复制了同样的圆和主体位置？
* 去掉蓝色以后，作品是否依然具有这套语言？
* 更换主题以后，几何系统是否随主题重新设计？

最后两个问题尤其重要。

# 一个成功案例的判断标准

假设主题被换成完全不同的内容，例如：

**“深海生物研究展”**。

最终画面中出现的是：

深海生物作为一级主体。

水深作为纵向坐标。

声呐作为圆形范围。

观测站作为节点。

物种编号作为索引。

移动路径作为轨迹。

水温、深度、采样时间成为微型信息。

蓝绿色承担观测状态。

颗粒模拟水下成像和设备采样。

它没有复制任何原参考素材，但第一眼仍然能够感受到：

**一个对象正在被一个复杂视觉系统观察、定位、记录。**

这就是成功迁移。

---

# 一个失败案例的判断标准

假设还是“深海生物研究展”。

设计师做了：

灰白背景。

中间放一条鱼。

周围放很多蓝圆。

加入几串随机数字。

随便写一个公式。

加英文 Lorem Ipsum。

叠一层噪点。

再加几条坐标线。

视觉上可能“有点像”，但：

圆没有定位对象。

数字没有索引。

公式没有内容关系。

所有几何都是装饰。

主题与结构互不影响。

把鱼换成汽车、人物或者建筑以后，整张图完全不需要改变。

这说明它复制的是**外观词汇**，没有复制到**设计逻辑**。

因此属于失败模仿。

---

整套规范可以进一步压缩成一句内部设计原则：

> **不要装饰主体，而要建立一个观察主体的系统。**
